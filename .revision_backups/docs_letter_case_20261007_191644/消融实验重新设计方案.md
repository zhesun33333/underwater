# UA-Bench 音频消融实验重新设计方案

## 1. 目的

音频消融的核心问题不是简单观察“去掉音频后准确率是否下降”，而是分别回答：

1. 模型是否能识别输入模态缺失并合理拒答；
2. 模型是否依赖提示词、类别频率或其他非声学先验；
3. 模型的预测是否会随音频内容改变；
4. 音频引起的预测改变是否朝正确类别移动，即音频是否被有效利用。

仅使用 text-only 不能完整回答这些问题。删除音频块会同时改变消息模板和模态结构，模型可能只是识别到“没有音频”并拒答，而不是因为失去声学证据才表现下降。

## 2. 当前实现的问题

当前 `testsite/ablation/text_only.py` 使用 `no_audio=True` 完全删除音频内容块，并沿用正常三级级联解析和计分。该实现存在以下局限：

- 没有独立统计拒答、缺失音频提示、有效回答和解析覆盖率；
- parser 会在整段回复中搜索类别别名，类似 “I cannot determine whether it is active or passive” 的拒答可能被误解析为有效类别；
- text-only 原始输出和消融指标没有写入独立、可审计的结果文件；
- 当前逐样本推理，没有利用已支持真 batch 的模型后端；
- T3 解释被生成但未用于 text-only 指标，造成额外推理成本。

在修正这些问题前，不应使用当前 text-only 输出形成论文结论。

## 3. 建议的四组条件

### 3.1 Full audio

输入原始音频，使用与正式评测完全相同的 prompts、级联规则、生成配置和解析器，作为配对比较基准。

### 3.2 Missing-modality control

完全删除音频内容块，仅保留相同文本提示。该条件保留，但命名为“缺失模态对照”，不再将其单独视为完整的音频消融。

主要观察：

- prompt-only 分类准确率；
- 模态缺失识别率；
- 拒答率；
- 模型在无音频时是否仍按类别先验猜测。

### 3.3 Length-matched silence control

保留音频内容块，为每条样本输入与原音频采样率、通道数和时长一致的全零波形。不要使用零采样点的空文件，也不要将所有样本统一成固定时长。

为节省磁盘空间，可以按照唯一 `(sample_rate, frames, channels)` 组合缓存静音 WAV，而不是为 2,600 条样本各保存一份。

该条件保留模态 token 和处理链路，只移除有效声学内容。它比 text-only 更接近严格的信号移除实验，但模型仍可能识别出全静音，因此不能单独作为音频依赖证据。

### 3.4 Label-mismatched real-audio control

为每条样本确定性地分配另一条真实音频，并尽量确保 donor 音频的目标标签与原样本不同。提示词和计分目标仍对应原样本，同时保存 donor 的 L1/L2/L3 标签。

推荐使用固定随机种子，并保存完整 permutation 映射，确保所有模型使用同一错配关系。可以按时长分桶后再错配，以降低音频长度分布变化带来的混杂。

该条件同时保留：

- 音频内容块和音频 token；
- 正常声学能量与结构；
- 与正式评测相近的输入分布。

它只切断原样本标签与实际输入音频之间的对应关系，是判断模型是否真正跟随音频的核心实验。

## 4. 拒答与有效回答检测

在类别解析前增加确定性状态检测，并保留以下相互独立字段：

```json
{
  "has_valid_label": false,
  "refusal_detected": true,
  "missing_audio_detected": true,
  "uncertainty_detected": true,
  "parsed_label": "unknown"
}
```

建议覆盖的中英文表达包括：

- `no audio`, `audio was not provided`, `cannot hear`, `cannot access the audio`；
- `unable to determine`, `insufficient information`；
- `没有提供音频`, `未检测到音频`, `无法听到`, `无法判断`, `信息不足`。

拒答与有效标签可以同时为真。例如模型先声明不确定，随后给出 forced choice，应继续按最终标签计算主准确率，同时计入“带猜测的拒答”。不得因为检测到拒答就直接丢弃输出。

parser 应优先识别明确最终答案，避免从解释、否定句或候选类别复述中任意匹配第一个别名。

## 5. 指标

所有条件统一报告：

- L1/L2/L3 Accuracy；
- L3 Macro F1；
- Parse Coverage / Valid Answer Rate；
- Refusal Rate；
- Missing-modality Acknowledgement Rate；
- 相对 Full audio 的逐样本准确率差值；
- 配对 bootstrap 95% 置信区间；
- Full 与消融条件之间的 Prediction Change Rate。

错配真实音频额外报告：

- Original-label accuracy：预测相对原样本 GT 的准确率；
- Donor-label accuracy：预测相对实际输入音频 GT 的准确率；
- Donor-following rate：换音频后预测转向 donor 标签的比例；
- 分层的 L1/L2/L3 donor-following rate。

若需要显著性检验，可对 Full 与每个对照的逐样本正确/错误状态使用 McNemar 检验，并以配对 bootstrap CI 作为主要不确定性报告。

## 6. 结果解释规则

- Full 显著优于 silence 和 shuffled-original：音频对正确分类有实际贡献；
- shuffled 后预测显著转向 donor 标签：模型确实跟随音频内容；
- 预测会变化但不转向 donor：模型对音频敏感，但未能有效解释音频；
- text-only 拒答高、silence 仍强制分类：模型主要检测模态是否存在；
- text-only 或 silence 仍有较高准确率：提示词先验、类别不平衡、时长或其他旁路信息可能贡献较大；
- Full 与 shuffled 几乎相同且预测不跟随 donor：缺乏音频依赖证据；
- silence 输出集中到少数类别：模型在无声学证据时发生类别先验坍缩。

不能只根据“消融后准确率降低”宣称模型使用了音频；应同时展示预测变化和 donor-following 证据。

## 7. 实施与计算顺序

推荐实现统一的 `audio_condition`，至少支持：

```text
full | missing | silence | shuffled
```

替代当前只有 `no_audio: bool` 的接口，并让所有条件复用同一批量推理路径。T3 是否执行应由实验目的决定；如果消融只比较分类依赖性，可仅运行 T1/T2，避免生成未被使用的解释。

推荐执行优先级：

1. Full audio（复用已有正式结果）；
2. Label-mismatched real audio；
3. Length-matched silence；
4. Missing modality / text-only。

每个条件必须保存：

- 完整 2,600 条预测；
- 原始回复；
- 拒答和解析状态；
- 原始样本与 donor 映射；
- 独立 metrics JSON；
- 随机种子、模型 revision、batch size 和运行配置。

在上述实现完成并通过小样本审计前，不将消融结果写入论文正文。
