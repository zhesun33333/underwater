# 水声大模型评估框架设计文档

---

## 一、框架总览

### 1.1 评估目标

本框架用于评估水声大模型在**层级分类任务**上的表现。模型接收一段水声信号音频，输出对该信号类型的三级层级分类结果。评估框架从四个维度衡量模型的分类能力。

### 1.2 分类体系

信号分类采用三层树状结构：

```
L1 (主动/被动)
├── active (主动信号)
│   ├── L2: pulse (探测脉冲类)
│   │   ├── L3: CW    — 连续波
│   │   ├── L3: LFM   — 线性调频
│   │   └── L3: HFM   — 双曲调频
│   └── L2: communication (通信类)
│       ├── L3: 2FSK  — 二进制频移键控
│       ├── L3: 4FSK  — 四进制频移键控
│       ├── L3: BPSK  — 二进制相移键控
│       ├── L3: QPSK  — 四进制相移键控
│       └── L3: OFDM  — 正交频分复用
└── passive (被动信号，⚠️ 目前只有一种，后续考虑补充生物声，或者拆分现有的部分为至少两类)
    └── L2: ship_noise (舰船辐射噪声)
        ├── L3: cargo            — 货船
        ├── L3: cruise           — 邮轮
        ├── L3: fishing          — 渔船
        ├── L3: warship          — 军舰
        └── L3: underwater_target — 水下目标
```

共 2 个 L1 大类，3 个 L2 子类，13 个 L3 具体类型。

### 1.3 设计原则

1. **超越 loss**：训练 loss 下降只能说明模型学会了语言模式，不能说明模型真正从音频中提取了信号特征。评估框架提供独立于训练的判别性测试。
2. **分层量化**：每一级分类分别评分，能定位错误发生在哪一层（是主动/被动都分不清，还是具体信号类型混淆）。
3. **多维验证**：不仅看"对不对"，还看"换种问法还对不对"（鲁棒性）、"换段音频会不会跟着变"（音频依赖性）、"两轮对话是否自洽"（推理质量）。
4. **可诊断**：混淆矩阵和 Per-class F1 能精确定位模型的薄弱类别。

```

```

## 三、核心模块详解

### 3.1 输出解析器 (core/parser.py)

所有 Prompt 均为选择题格式（给出 A/B/C/... 选项）。模型可能返回两种形式的答案：
- **短答案**：仅输出选项字母，如 `"A"` 或 `"A."`
- **长答案**：输出带有选项文本的完整句子，如 `"这是A. 主动信号-探测脉冲类-CW连续波，因为..."`

解析器分两个阶段处理：

**阶段一：选项字母还原 (`resolve_short_answer`)**

当模型输出很短（≤8 字符）时，从 Prompt 中提取选项映射表（`"A. 主动信号-探测脉冲类-CW连续波"` → `{"a": "主动信号-探测脉冲类-CW连续波"}`），将模型输出的字母还原为完整选项文本。

```
模型输出: "A"
Prompt:   "... A. 主动信号-探测脉冲类-CW连续波  B. 主动信号-探测脉冲类-LFM线性调频 ..."
                          ↓ resolve_short_answer()
还原文本: "主动信号-探测脉冲类-CW连续波"
```

**阶段二：Alias 关键词匹配 (`_extract`)**

在文本中搜索 taxonomy config 中定义的别名，采用两轮回退：

| 层级 | 机制 | 说明 |
|------|------|------|
| **Tier 1** | Alias 直接匹配 | 大小写不敏感搜索别名（如 "CW"、"连续波"、"货船"），按别名长度降序（长别名优先，防止 "CW" 误匹配 "CW连续波" 更长的别名） |
| **Tier 2** | 去标点宽松匹配 | 去掉所有非字母数字字符后再匹配，处理标点变体 |
| **Tier 3** | 失败兜底 | 返回 "unknown" |

```python
# parse() 入口
def parse(self, sample_id, model_output, prompt=""):
    if prompt:
        model_output = resolve_short_answer(model_output, prompt)  # 阶段一
    text = model_output.strip()
    l1, _ = self._extract(text, self.l1_map)  # 阶段二: 匹配 "主动信号"→active
    l2, _ = self._extract(text, self.l2_map)  # 匹配 "探测脉冲类"→pulse
    l3, _ = self._extract(text, self.l3_map)  # 匹配 "CW"→CW
```

所有 eval 模块（classify、robustness、audio_dependency、multi_turn）在调用 `parser.parse()` 时都将 Prompt 作为参数传入，确保选项字母能被正确还原。

### 3.2 指标计算引擎 (core/scorer.py)

所有指标由 `Scorer` 类的独立方法计算，每类指标有对应的 dataclass 数据结构。

#### 第一层指标：层级分类

| 指标 | 定义 | 含义 |
|------|------|------|
| **L1/L2/L3 Accuracy** | 该层级预测正确的样本占比 | 各级独立的分类正确率 |
| **L3 Macro F1** | 13 个 L3 类别的 F1 未加权平均 | 不受类别样本量不均影响 |
| **Joint Accuracy** | L1+L2+L3 三级全部正确的样本占比 | 最严格的综合指标 |
| **L2\|L1** | L1 正确的前提下 L2 正确的概率 | 排除 L1 错误对 L2 的级联污染 |
| **L3\|L2** | L2 正确的前提下 L3 正确的概率 | 排除上层错误对 L3 的级联污染 |
| **Per-class F1** | 每个 L3 类别的 Precision/Recall/F1 | 定位薄弱类别 |
| **混淆矩阵** | 13×13（+ unknown/cascade 特殊列） | 可视化类别间误判模式 |

#### 第二层指标：跨模板鲁棒性

| 指标 | 定义 |
|------|------|
| **L1/L2/L3 Agreement Rate** | 同一条音频用 5 种不同措辞问，该层级答案一致的比例 |
| **Full Agreement Rate** | 5 次回答三级标签全部一致的比例 |

#### 第三层指标：音频依赖性

| 指标 | 定义 |
|------|------|
| **Diff-Audio Diff-Answer Rate** | 对不同类别音频用相同 Prompt，L3 答案不同的样本对占比。越高越好（max=1.0 表示模型对每对不同音频都给出了不同答案） |
| **SNR 退化曲线** | 按 `snr_after_channel_db` 分组后各 SNR 档位的 L3 Accuracy |

#### 第四层指标：推理质量

| 指标 | 定义 |
|------|------|
| **Turn Consistency** | Turn1 和 Turn2 输出的 L1 一致的比例 |
| **L2/L3 Consistency** | L3 确实属于 L2 子类的比例（如 L3="CW" 的 parent 必须是 "pulse"） |
| **Domain Term Match** | 推理文本中匹配到水声领域术语（如"时频图"、"调频"、"线谱"、"子载波"等）的比例。衡量模型是否基于声学概念做判断，而非盲猜。不同于参数估计——不要求模型输出精确数值 |

### 3.3 模型推理接口 (core/inference.py)

统一的 `ModelInference` 类，通过 config 中的 `backend` 字段切换：

| 后端 | 说明 |
|------|------|
| **mock** | 用于测试框架。MockModel 根据音频路径中的信号类型关键字生成仿真输出，按 config 中的 accuracy 参数控制模拟的 L1/L2/L3 正确率 |
| **qwen2_audio** | Qwen2-Audio-7B-Instruct，通过 HuggingFace transformers 加载。支持单轮 `generate()` 和多轮 `chat()` 两种模式 |
| **qwen2_audio_finetuned** | 同 qwen2_audio，用于加载微调后的 checkpoint |

`Qwen2AudioBackend` 的实现细节：
- 使用 `Qwen2AudioForConditionalGeneration` + `AutoProcessor`
- 音频通过 `librosa.load()` 加载为 numpy 数组，resample 到模型的 feature_extractor 采样率
- 多轮对话通过 Qwen2 的 chat template 构建，音频仅在第一轮 user message 中嵌入
- 推理使用贪婪解码（temperature=0），确保评估可复现

### 3.4 数据加载器 (core/loader.py)

从 Step 2 产出的 JSONL 文件加载评估样本：

1. 逐行读取 JSONL，提取 `id` 和 `audio` 字段
2. 根据 `audio` 路径结构推断对应的元数据 JSON 位置（PulseCom: `PulseCom/jsonc/<type>/<id>.jsonc`；Ship: `05_ship_radiated_noise/<class>/json/<id>.json`）
3. 若路径推断失败，用 `sample_id + .jsonc/.json` 递归搜索
4. 从元数据 JSON 中提取 L1/L2/L3 ground truth（通过 `extract_l1_l2_l3_from_meta()` 函数，映射 `signal_category`/`signal_type`/`sub_type` 到 taxonomy keys）
5. 构造 `EvalSample(sample_id, audio_path, gt, metadata)`

找不到元数据的样本 GT 记为 "unknown"，参与评估但不会被计为正确。

### 3.5 报告生成器 (reporting/report.py)

生成 Markdown 格式的评估报告，包含 8 个章节：

1. **层级分类评估** — L1/L2/L3 Accuracy + Macro F1，L3 各类别 P/R/F1/Support 表，L3 混淆矩阵（8×8 截断），Top-5 易混淆对
2. **层级联合指标** — L2|L1、L3|L2、Joint Accuracy
3. **跨模板鲁棒性**（--all）— N 样本 × M 模板的各级一致率
4. **音频依赖性**（--all）— Diff-Audio Diff-Answer Rate
5. **SNR 退化曲线**（--all）— 各 SNR 档位的 L3 Accuracy
6. **推理质量**（--all）— Turn Consistency、L2/L3 Consistency、参数引用率
7. **答案解析层级分布** — Tier 1/2/3 的样本数分布（排查解析器问题）
8. **结论与建议** — 自动判断：L3 Acc 是否达标（>90%/75-90%/<75%），最弱类别，L2|L1 诊断，L1 诊断

## 四、四层评估设计

### 4.1 第一层：层级分类（单轮）

**目的**：衡量模型最基础的单轮分类能力。

**方法**：对每条样本，使用固定 Prompt 做单轮推理，解析出 L1/L2/L3，与 GT 逐级比对。

**Prompt**（来自 config `prompts.audio_dep.question`，选择题格式，13 个选项覆盖全部 L3 类型）：
```
请判断这段水声信号的完整类型。
选项：
A. 主动信号-探测脉冲类-CW连续波
B. 主动信号-探测脉冲类-LFM线性调频
C. 主动信号-探测脉冲类-HFM双曲调频
D. 主动信号-通信类-2FSK
E. 主动信号-通信类-4FSK
F. 主动信号-通信类-BPSK
G. 主动信号-通信类-QPSK
H. 主动信号-通信类-OFDM
I. 被动信号-舰船辐射噪声-货船
J. 被动信号-舰船辐射噪声-邮轮
K. 被动信号-舰船辐射噪声-渔船
L. 被动信号-舰船辐射噪声-军舰
M. 被动信号-舰船辐射噪声-水下目标
请给出选项字母，并简要说明你的判断依据。
```

**输出指标**：全部第一层指标（L1/L2/L3 Acc, Macro F1, Joint, 条件准确率, Per-class F1, 混淆矩阵）。

**设计理由**：这是最基础也是最核心的评估。后续三层都是在此基础上的增强诊断。默认模式（不加 `--all`）只跑这一层。

### 4.2 第二层：跨模板鲁棒性

**目的**：检测模型是否对 Prompt 措辞敏感。如果模型真正学会了从音频中提取分类信息，换一种问法应该得到相同的答案。

**方法**：对同一条音频使用 **5 种不同措辞**的 Prompt 各推理一次，检查 L1/L2/L3 答案是否全部一致。

**5 种 Prompt 变体**（来自 config `prompts.robustness`，均为选择题，选项为 A-M 共 13 项，措辞不同但选项内容相同）：

| # | Prompt 问法（选项均为 A-M 13 项，此处省略选项文本） |
|---|--------|
| 1 | 请判断这段水声信号的完整类型。 |
| 2 | 识别这段音频中的水声信号，从以下选项中选择。 |
| 3 | 这段信号是什么？请按主动/被动 → 子类 → 具体类型的层次选择。 |
| 4 | 请对这段水声信号做分类，从以下选项中选出正确答案。 |
| 5 | 听这段音频，判断其中水声信号的三级分类，从选项中选择。 |

每条 Prompt 后均附带相同的 13 个选项（A-M），覆盖全部 L3 类型。完整 Prompt 示例见 config `prompts.robustness`。

**输出指标**：L1/L2/L3 Agreement Rate、Full Agreement Rate。

**设计理由**：如果 L3 Agreement Rate 低，说明模型没有稳定地从音频中提取特征，而是在"猜 Prompt"（给出了问法 A → 答案 X 的表面映射）。这是检测数据集**模板坍缩**的关键指标。

### 4.3 第三层：音频依赖性

**目的**：验证模型是否真正在"听"音频，而非仅仅从 Prompt 文本中猜测。

**子测试 A — Diff-Audio Diff-Answer**：

对不同类别的音频对（确保 GT 的 L3 不同），使用**完全相同的 Prompt** 各推理一次。如果模型确实在根据音频内容做判断，那么两段不同类别的音频应该得到不同的 L3 答案。

```
样本 A (LFM脉冲) + Prompt → 模型答案: LFM
样本 B (货船)    + 相同 Prompt → 模型答案: 货船
→ L3 不同 ✓ (这对样本视为"可区分")
```

Diff-Audio Diff-Answer Rate = 可区分的样本对数 / 总样本对数。**越高越好**，1.0 表示每对不同音频模型都给出了不同的 L3 答案。

**子测试 B — SNR 退化**：

按 `snr_after_channel_db`（来自 Step1 产出的元数据）将样本分组到最近的 SNR 档位（-10, -5, 0, 5, 10, 15, 20 dB），分别计算各档位的 L3 Accuracy，观察分类能力随信噪比下降的退化规律。预期：高 SNR 样本的分类准确率应高于低 SNR 样本。

**设计理由**：子测试 A 是"换音频后答案是否跟着变"的最直接测试。如果模型不管输入什么音频都输出相同答案（Diff-Audio Diff-Answer ≈ 0），说明模型没在听音频。子测试 B 衡量模型在不同噪声水平下的鲁棒性，判断模型的实用边界。

### 4.4 第四层：推理质量（两轮对话）

**目的**：评估模型在多轮对话中是否自洽，以及推理过程是否引用信号参数。

**方法**：

```
Turn 1: 问 L1（主动还是被动）
    → 模型回答
    → 解析 L1
    → 如果 L1 正确 → 继续 Turn 2
    → 如果 L1 错误 → 级联终止，L2/L3 记为 cascade_error

Turn 2: 根据 L1 方向，追问具体类型
    → "好的，{主动信号/被动信号}。请进一步判断它是脉冲信号还是通信信号，给出具体类型和判断依据。"
    → 或 "好的，{被动信号}。请判断这属于哪类舰船或水下目标的辐射噪声，给出依据。"
    → 解析 L2+L3
```

**关键设计决策 — 级联终止**：Turn1 的 L1 判断错误时，不继续追问 Turn2。如果 T1 错误地把"被动信号"判为"主动信号"，追问 "好的，主动信号。请进一步..." 会把模型推入错误的子树（脉冲/通信），模型不可能给出正确答案。此时跳过 Turn2，L2/L3 记为 `cascade_error`，不参与 Turn2 指标。

**Two-turn Prompts**（来自 config `prompts.two_turn`，均为选择题）：

Turn1（随机选一个，选项固定为 A/B）：
- "请判断这段水声信号是主动发射的还是被动接收的。\n选项：\nA. 主动信号\nB. 被动信号"
- "这段音频中的信号是主动声纳发出的，还是被动监听到的？\n选项：\nA. 主动信号\nB. 被动信号"
- "先判断最基本的问题：这信号是主动式的还是被动式的？\n选项：\nA. 主动信号\nB. 被动信号"

Turn2（根据 L1 方向选择对应的模板，均追加 "请给出选项字母，并简要说明你的判断依据"）：
- active:  "好的，{L1}。请进一步判断它是脉冲信号还是通信信号，给出具体类型。\n选项：\nA. 主动信号-探测脉冲类-CW连续波\n...H. 主动信号-通信类-OFDM\n请给出选项字母，并简要说明你的判断依据。"（8 个选项）
- passive: "好的，{L1}。请判断这属于哪类舰船或水下目标的辐射噪声。\n选项：\nA. 被动信号-舰船辐射噪声-货船\n...E. 被动信号-舰船辐射噪声-水下目标\n请给出选项字母，并简要说明你的判断依据。"（5 个选项）

**输出指标**：Turn Consistency（T1 和 T2 的 L1 一致率）、L2/L3 Consistency（L3 和 L2 的父子关系是否匹配）、Domain Term Match Rate（推理文本中是否匹配水声领域术语）。

**设计理由**：水声信号分析在真实场景中通常是多轮交互的——先判断信号来源方向，再在该方向下细化。级联终止避免了"一个错误导致后续全部无效"的评估污染。

## 五、Prompt 设计

### 5.1 设计原则

1. **选择题格式**：所有 Prompt 均给出明确的选项列表（A/B 或 A-M），模型输出 `"{选项字母}。{定性推理}"` 格式。
2. **选项文本自包含层级信息**：每个选项字符串本身携带 L1/L2/L3 三级信息（如 `被动信号-舰船辐射噪声-货船`），解析器可直接从中提取 taxonomy key。
3. **定性推理防止模板坍缩**：训练数据的 `gpt` 答案包含随机选取的定性推理文本（如 `"B。时频图中可见频率线性上升的条纹，符合调频特征。"`），每个 L3 类型有 3-4 种不同句式。推理文本只描述信号可从音频中学到的模式级概念（"频率线性变化"、"多子载波结构"），不包含精确数值，避免强迫模型做不可学的数值估计。
4. **多样性覆盖**：鲁棒性测试的 5 种 Prompt 在措辞、句子结构、信息顺序上各有不同，但选项列表完全一致。
5. **不暴露内部键名**：Prompt 中不出现 "active/passive" 或 "L1/L2/L3" 等代码内部标签，选项文本使用中文自然语言。

### 5.2 选项解析的设计

解析器不硬编码字母到 taxonomy key 的映射（不写死 `{"A": "CW"}` 这样的表）。而是利用 Prompt 中的选项文本：`resolve_short_answer()` 从 Prompt 中提取 "A. 主动信号-探测脉冲类-CW连续波" → 映射 `{"a": "主动信号-探测脉冲类-CW连续波"}` → alias 匹配器再从中提取 `active` / `pulse` / `CW`。

这种设计的好处：
- 修改 Prompt 选项时无需同步修改解析器映射表
- 新增信号类型时只需在 taxonomy config 中添加 aliases
- 选项文本和 taxonomy aliases 保持单一数据源

## 七、评估指标优先级

| 优先级 | 指标 | 使用场景 |
|--------|------|---------|
| **P0** | L3 Accuracy, L3 Macro F1 | 每次评估必看，论文主表 |
| **P0** | Joint Accuracy | 三级全对率，最严格 |
| **P1** | L2\|L1, L3\|L2 | 定位错误发生在哪一级 |
| **P1** | Per-class F1 + 混淆矩阵 | 找出模型的最弱类别 |
| **P2** | L1/L2/L3 Agreement Rate | 验证鲁棒性，加 --all |
| **P2** | Turn Consistency | 验证多轮自洽，加 --all |
| **P3** | Diff-Audio Diff-Answer | 验证音频依赖，加 --all |
| **P3** | SNR 退化曲线 | 噪声鲁棒性，加 --all（需 SNR 元数据） |
